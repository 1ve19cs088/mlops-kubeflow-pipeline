# Everything the offline training pipeline (src/) needs at runtime —
# matplotlib for confusion matrix plotting, PyYAML for config loading,
# kfp for Kubeflow pipeline compilation, docker for kfp.local's
# DockerRunner (local pipeline execution), mlflow-skinny for experiment
# tracking + model registry. None of this belongs in the serving image.
#
# mlflow-skinny, not the full mlflow package: mlflow (full) hard-pins
# pandas<3 and cryptography<50, both incompatible with this project's
# existing pins (pandas==3.0.5 was deliberately chosen — see the
# feature_engineering dtype fix earlier in this project's history).
# mlflow-skinny provides the same tracking client, model registry, and
# mlflow.sklearn.log_model API with no such constraint.
#
# sqlalchemy + alembic are required explicitly: mlflow-skinny alone
# does NOT bundle them, but MLflow's SQL-backed model registry store
# needs them to support a sqlite:// tracking URI at all — without them,
# mlflow raises UnsupportedModelRegistryStoreURIException. This was
# missed in initial local verification because a stray earlier
# `pip install mlflow` (full package, later uninstalled) had left both
# packages behind in that dev venv, masking the real requirement; a
# genuinely clean install (matching CI) surfaced it.
